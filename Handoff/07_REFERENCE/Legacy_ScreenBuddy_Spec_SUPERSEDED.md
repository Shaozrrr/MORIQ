## 0. 首先读这里：不可改动的决定

1. **这是原生 Mac 桌面应用，不是网站，也不是套壳网页。** SwiftUI 实现设置与内容组件，AppKit 实现全局浮窗、窗口行为和系统交互；需要的底层能力使用 Apple 原生框架。
2. **主窗口只能是简洁功能控制中心**，主要展示功能名、极简一句话描述、`演示` 按钮、真实的开关。不要文件上传区、拖放区、聊天页面、最近记录大卡片、工作台仪表盘、冗余指标、底部固定动画区、推荐文章、商城。
3. **点击一项功能的「演示」才弹出一个独立演示窗口**。动画区域尽可能大；**「↻ 重新播放」只放在动画画面的右上角**；右上角另有关闭按钮（位于弹窗顶部标题栏，不能遮挡重播按钮）；**没有底部状态文案和底部控制条**。动画自己包含必要的操作提示，不要页面下方重复解释。
4. **真实功能发生在用户本来正在工作的桌面、Finder 和其他 App 上**；设置窗口没有义务承载文件操作。
5. **V1 五个功能**：①万能转换圆盘，②屏幕 AI 助手 ScreenBuddy，③悬浮文件暂存架，④智能剪贴板历史，⑤超级截图（包括 OCR、翻译、标注、贴图、发送给 AI）。不再随意增加大功能。
6. **品牌**：ScreenBuddy。固定色：`#000000`、`#FFFFFF`、亮蓝 `#2563FF`。系统灰度仅用于边框、阴影、禁用态及背景层级，不另加装饰性色。遵循用户此前选定的黑色倾斜屏幕 + 蓝色错位底板 Logo；菜单栏适配纯黑/纯白图标、不要额外方形边框。不擅自换 Logo。
7. **动效要精致但不能打扰操作**：有弹簧、磁吸、形变和短促反馈；绝不以过长炫技动画增加等待。支持 macOS“减少动态效果”。
8. **AI V1 严格 BYOK**：用户自备 API Key；不提供平台代付 Token、不使用 ChatGPT/Codex 登录直接计费、不做订阅计费系统。设置内提供获取 API Key 的清晰说明；Key 存 macOS Keychain。
9. **屏幕隐私**：默认用户明确点击/触发时才获取屏幕截图；持续感知必须单独手动打开，有明显状态提示、即时停止入口、可解释的更新频率；**截图不自动上传模型**，上传前必须有可理解的授权和内容范围。默认本地优先。
10. **不吹嘘系统权限**：不同功能需要不同授权；需要时再申请，不在首次启动时弹出五个权限框。文件安全、权限、后台资源消耗的承诺以实际测试为准。

## 1. 产品一句话、用户和成功标准

**一句话**：ScreenBuddy 把 Mac 常用的文件转换、截图/翻译、屏幕 AI、剪贴板和暂存架做成随时出现、用完就消失的系统级工具。

**用户**：每天用 Mac 处理文件、浏览网页、写文档、开发、读英文资料的学生和办公用户。经常切换软件、不希望为小操作打开独立网站和多个工具。核心使用者看重快速、好看、无需复杂配置。

**不是**：浏览器文件转换站、常驻 AI 聊天网页、重型自动化 IDE、24 小时监控电脑的 AI Agent、复杂视频编辑器。

**最小成功体验**：安装 → 启动后出现一个很小的欢迎/权限解释 → 菜单栏常驻 → 使用快捷键或文件拖动唤出对应能力 → 操作完成后不打断当前工作 → 设置里能关闭每项功能并看到独立动画演示。

**V1 必须达到的用户结果**：
- Finder 中可触发圆盘，把受支持图片真正转换成目标格式，原文件不变。
- 快捷键能打开 AI 助手，用户输入自己的 API Key 后可真正对话，可在获授权后将选区或截图交给 AI。
- 文件拖到屏幕边缘能进入暂存架，拖出来能继续用，重启后按设置恢复，原文件不被搬走。
- 剪贴板历史能搜索、复制/粘贴与清理；能跳过敏感类型与指定 App。
- 超级截图能框选、复制、OCR、翻译、标注、贴图；文字翻译有实际结果，原位覆盖翻译可作为较高级的 V1 进阶验收项（见 7.5）。

**质量门槛（目标，不代表已有实测）**：常用浮窗触发主观上立即响应；不出现窗口焦点被偷走后无法返回原 App；不覆盖原文件；长时间常驻不会明显吃内存/CPU；单次失败有提示且可重试；在多显示器、全屏、不同缩放下不越界。

## 2. 信息架构：只要一个很小的设置主窗口

### 2.1 进入方式

- 安装并首次打开后引导开启“登录时启动”，由用户决定；菜单栏有 ScreenBuddy 图标。
- 点击菜单栏图标：`打开设置` / `暂停全部工具` / `检查更新`（发布版支持后） / `退出 ScreenBuddy`。菜单尽量简短。
- 主窗口推荐基准 **宽 520–620pt、高随 5 行设置自适应**；不占满屏幕、不能像 SaaS 侧边栏网站。圆角应以系统窗口表现为主，不要模拟红黄绿控制点来替代真实窗口装饰。

### 2.2 主窗口结构

顶部：左侧品牌标记和“ScreenBuddy”；右侧可有极简设置图标（进入少量高级设置）。内容区：标题“功能设置”，副标题“需要时出现，用完即消失”，下面**恰好五行**：

| 位置 | 功能名 | 一行说明（UI 原文） | 右侧 |
|---|---|---|---|
| 1 | 万能转换圆盘 | 拖动文件时按 ⇧ Shift | `演示` + `开关` |
| 2 | 屏幕 AI 助手 | ⌘ ⇧ Space 唤醒 | `演示` + `开关` |
| 3 | 文件暂存架 | 拖动文件至屏幕边缘 | `演示` + `开关` |
| 4 | 智能剪贴板 | ⌘ ⇧ V 查看历史 | `演示` + `开关` |
| 5 | 超级截图 | ⌘ ⇧ X 截图、翻译和贴图 | `演示` + `开关` |

说明：以上为**暂定默认快捷键**，必须实现冲突检测和重新设置；macOS/第三方已有快捷键冲突时不能强制覆盖。系统对某些组合可能有限制，需真机验证。关闭任何开关都应真实停止相关监听/任务/定时器，而非只改变 UI 外观。已打开的浮窗在关闭对应模块时立即退出并清理资源。

主窗口不要：固定演示预览、动画操作步骤大段文字、七八个二级标签页、统计数据、文件管理器、聊天历史展示。要高级感来自留白、字体、细腻反馈，不靠堆元素。

### 2.3 次级设置（仅在确有必要时展示）

主窗口右上角一个设置入口打开简洁分组：
- 通用：开机启动、菜单栏图标、暂停全部、语言（中文默认，英文后续）、更新。
- 快捷键：每个全局快捷键可录制与恢复默认；冲突即时提醒；圆盘多个模式的键位可调整。
- AI：服务商、模型、Keychain 密钥输入与验证、获取 Key 教程、每次截图是否需确认（默认确认）、上下文保留时长；不显示任何“充值 Token”。
- 隐私：剪贴板排除名单、清除历史、截图传输策略、连续感知说明、本地文件储存与删除。
- 外观：深浅模式跟随系统优先；减少动态效果跟随系统；可调整动效偏好，不必做花哨主题市场。

### 2.4 演示弹窗结构——已经最终确认，绝不能擅改

点击某行的“演示” → 设置窗口**上方弹出独立演示面板**（演示不是主设置页的一部分）→ 面板顶部标题简短，右上有 `×` → **下方是大块 Mac 桌面动画舞台** → **「↻ 重新播放」按钮悬浮在动画画面右上角**，与关闭按钮属于不同层，不重叠 → **没有舞台下方固定说明文字、底部按钮栏或额外操作按钮**。动画自动开始，结束后停留在最终状态；重新播放后完整重置。Esc 关闭演示，焦点返回原主窗口。动画中的 Finder 只是示意场景，不是文件操作入口。

**弹窗示意**：
```
╭────────────────────────────────────────────╮
│ 万能转换圆盘                           ×  │
├────────────────────────────────────────────┤
│ ╭──────────── Mac 桌面动画 ───────────────╮ │
│ │                          ↻ 重新播放    │ │
│ │ Finder 窗口、文件、鼠标、浮出的圆盘      │ │
│ │        [动画阶段在此区域发生]            │ │
│ │             [Dock 场景]                  │ │
│ ╰──────────────────────────────────────────╯ │
╰────────────────────────────────────────────╯
```
- 动画可以展示非常简短的阶段文字，但**只允许出现在动画场景中短暂浮现**；若画面已经清楚，优先不显示任何提示。
- 重新播放的按钮不应覆盖动画主体、鼠标路径或顶部 Finder 菜单栏，必要时给安全区。
- 独立演示组件支持不同类型的脚本和重复播放；不执行真实文件转换、OCR 或 AI 请求。

## 3. 统一视觉设计规范

### 3.1 品牌与配色

- 纯黑：`#000000`，用于标题、品牌标记、部分重要悬浮组件底色。
- 纯白：`#FFFFFF`，用于设置窗口内容、浮层文字。
- 品牌蓝：`#2563FF`，用于开关开启、当前选中格式、进度条和少量重点交互。
- 中性色：从系统 `labelColor`、`secondaryLabelColor`、`separatorColor`、`windowBackgroundColor` 派生；浅色布局可参考 `#F5F5F7`、`#E7E7EB`，但不再引入其他装饰主色。
- Mac 桌面演示里的 Finder 窗口、系统桌面背景可使用系统的常规颜色模拟环境，**不视为产品品牌新增配色**。
- 所有按钮使用相同语义，蓝色不可到处滥用：品牌蓝主要用于“开”、当前选择与重要确认；不可整屏蓝色渐变。

### 3.2 排版、形状与间距

- 字体：macOS 系统 `SF Pro`，中文自动使用系统中文字体；优先 SwiftUI 系统字体而不是下载外部字体。
- 层次建议：窗口大标题 20–23pt / semibold；功能名 13–14pt / semibold；一句描述 11–12pt / regular；演示按钮 12pt。
- 以 4pt 为间距基元；主要边距 20–28pt；设置行上下留白 14–17pt，图标 34–40pt；按钮圆角 8–10pt，浮窗圆角 16–22pt。
- 不做复杂玻璃拟态：只在系统级浮层、菜单或演示环境上少量使用材质/模糊；主体保持纯净。
- 图标选 SF Symbols，并统一描边权重；禁止 emoji 替代正式图标，不能混搭五种图标风格。

### 3.3 五种视觉对象

1. **设置主窗口**：白底/系统适配，黑标题，细分割线，极少元素。开关蓝色，其他灰度。
2. **转换圆盘**：鼠标周围独立黑色环形窗，白色标签，蓝色悬停扇区；中心显示原格式/当前操作；分级子圆盘有连续的空间展开反馈。
3. **AI 胶囊**：屏幕底部中央，黑色窄胶囊（如 135×42pt）亮蓝细边光或细小动态核心；输入时变成宽而不高的交互面板，复杂回答可展开高度但不得覆盖半屏。
4. **文件暂存架**：侧边半隐藏黑色窄条，靠近/拖入时展开，可看见整齐文件缩略图；边缘磁吸和轻微弹性回弹。
5. **截图工具条**：紧贴选区的低干扰黑色短条，白色 SF Symbol；当前功能蓝色；选区框用清晰蓝线和小控制点；OCR/翻译结果另有小浮窗，不强制弹主窗口。

### 3.4 动效规范（设计目标，不是已经测量的数据）

- 开关：180–250ms，圆点有轻微弹性，切换后立刻触发对应模块的真实状态改变。
- 主设置窗口：遵循系统原生动画；不做网站式全屏滑动页面。
- 演示弹窗：淡入 + 缩放，约 250–350ms；关掉比打开稍快；减弱动态模式仅淡入淡出。
- 圆盘：展开 250–400ms，初始略缩小并旋转、随即稳定；悬停 80–140ms 内改变高亮；松手后快速收拢并给出约 1 秒非阻塞成功提示。
- AI：按快捷键后迅速出现小胶囊；正文输入/截图选择时宽度先扩展、高度再扩展，避免一瞬间大面积遮挡；关闭做反向形变。
- 暂存架：边缘磁吸以 120–220ms 呈现，隐藏应有防抖延迟，不能鼠标刚离开立即消失。
- 截图：选区出现时略微压暗未选区背景，放开鼠标后工具条微小上浮；OCR/翻译时保留可见的处理中状态，不无限旋转。
- 必须尊重 `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` 与 SwiftUI `accessibilityReduceMotion`，禁用多余位移、脉冲和旋转。
- 任何动画绝不阻塞真实任务；任务状态由真实操作驱动，不能用 `sleep(1.5)` 伪造处理成功。

## 4. 实际触发和窗口位置（重点）

| 功能 | 真正触发 | 真正出现位置 | 用户怎么完成 | 怎么关闭/取消 |
|---|---|---|---|---|
| 转换圆盘 | Finder/桌面或支持文件拖拽的 App 内，**拖动文件期间轻按 ⇧** | 当前鼠标周围；靠近边缘时自动避让 | 拖到扇区，松开文件；可方向键+回车作为辅助 | Esc/拖到中心/释放在取消区；取消不得生成半文件 |
| AI 助手 | 默认 `⌘ ⇧ Space` | 当前显示器底部中央（不是设置窗口内部） | 输入问题；可选择截图、当前选区；发送后流式回复 | Esc、快捷键再次触发、明确的收起入口 |
| 文件暂存架 | 拖动文件触达屏幕边缘的热区；也可从圆盘“暂存”操作进入 | 文件正在接近的屏幕左/右边缘，避让 Dock 和刘海/菜单栏 | 拖入暂存；点击 Quick Look；拖出去使用 | 延迟收起；可手动关闭或清空；原文件不动 |
| 剪贴板历史 | 默认 `⌘ ⇧ V` | 当前指针附近或屏幕中心偏上，避让屏幕边缘 | 搜索、选中并复制/粘贴、固定收藏 | Esc、粘贴、点击外部 |
| 超级截图 | 默认 `⌘ ⇧ X` | 整屏半透明选区覆盖层；完成后工具条贴选区 | 框选→复制/OCR/翻译/标注/贴图/问 AI | Esc取消选区，或执行后自动收起；贴图有关闭入口 |

**多显示器原则**：用户触发时鼠标所在的 `NSScreen` 是优先显示器。将鼠标位置转换成对应屏幕的坐标系。避免只使用主显示器 `NSScreen.main` 导致显示错误。全屏应用、Stage Manager、不同缩放、竖屏显示器均需专门测试。

## 5. 功能一：万能转换圆盘

### 5.1 具体用户故事

我在 Finder 里按住一张 `.heic` 图片并拖动，轻按 Shift。鼠标旁出现一个环形菜单，看到 JPG、PNG、PDF 等可选项目。拖到 JPG 扇区，松手后在源目录得到一个 JPG；原来的 HEIC 还在。如果当前目录有同名 JPG，自动生成不覆盖的名称。失败时轻提示原因，文件不丢。

### 5.2 V1 行为

- 识别单个和多个文件；动态列出可行操作，**不显示当前引擎不能真正写出的格式**。
- 初始模式是“转换”。可在按键/滚轮切到“工具”和“操作”圆盘，借鉴 Swivel 的三模式概念，但初版不强迫用户学多个键位。
- 转换：图片至少 HEIC/JPEG/PNG/TIFF/PDF（逐个按系统编解码器实测）；视频音频基础支持作为次级交付，统一由能力查询决定显示；不得写死所有格式均可转换。
- 工具：图片压缩、改尺寸、旋转、裁切；PDF 合并/拆分、OCR 入口（视引擎可用性）；危险动作需明确确认。
- 操作：复制文件路径、Quick Look、显示详情、发送到暂存架。
- 图片首版允许针对常见像素格式实现可靠转换；WebP 输出、MKV、MP3 等可能需要外部编码器，没打包之前**不能在圆盘上假显示可用**。
- 批量选中时只显示全部文件都支持的公共操作，或者清楚标示将跳过的文件及原因。
- 操作结果放源文件旁或由用户指定；原文件保持不变；异常中断清理临时文件；重名时使用独占保存策略。

### 5.3 底层实现（已实际读过 OpenShelf DragMonitor.swift）

- `DragMonitor` 使用 `NSEvent.addGlobalMonitorForEvents(matching: .leftMouseDown)` 和 `.leftMouseDragged` 检测按下与拖动，同时添加本地事件监听；通过 `NSEvent.pressedMouseButtons` 判断是否仍保持左键按下。
- 保存 `NSPasteboard(name: .drag).changeCount` 的拖拽前值，拖拽期间检查是否改变且 `types` 包含 `.fileURL`；随后用 `readObjects(forClasses: [NSURL.self], options: [.urlReadingFileURLsOnly:true])` 获取文件 URL。
- 按需高频跟踪：OpenShelf 源码里拖拽期间约 **16ms** 间隔，空闲兜底约 **1 秒**；修饰键组合有 **70ms** 稳定时间。避免在闲置桌面上持续高频轮询。
- 通过 `NSEvent.modifierFlags` 或适当键位状态判断热键，谨慎区分正常拖动和“按键触发”；使用局部/全局监听的权限边界按 Apple 文档处理。
- `NSPanel` 浮窗应选择合适 `styleMask` 和不抢焦点的行为，防止普通 Finder 拖拽失效。**真实放开鼠标后能否可靠完成原始文件拖放并获取最终扇区**需要在不同应用实际验证；不能仅在动画中假定完美成立。
- 圆盘依据 `NSEvent.mouseLocation` 决定中心；边缘位置自动翻转/偏移，保证各扇区都可见。
- 使用状态机：`idle → pressTracking → dragConfirmed → wheelOpen → segmentHighlighted → executing → completed/failed/cancelled → idle`。每次释放后必须重置状态。

### 5.4 文件处理与安全

- 图像转换：`ImageIO` / `CoreGraphics`；图片元数据保留/移除为可选操作；考虑 EXIF Orientation 和色彩空间。
- PDF：`PDFKit`，扫描 OCR 用 `Vision`。
- 视频音频：`AVFoundation` 等系统框架；对系统无法编码的格式明示不支持，后续再评估可选 FFmpeg。
- 转换任务交给 `ConversionEngine`（不放在 SwiftUI View 内）；队列限制并发，长任务支持取消/超时及清理。
- 写入随机临时文件 → 真实格式校验 → 原子或排他性移动到目标目录；需要时采用 `renamex_np(..., RENAME_EXCL)` 或等效“不覆盖”方案；文件名碰撞自动 `name 2.ext`；失败留下原文件且不留下半成品。
- ZIP 等归档提取必须阻止 `../` 路径穿越、绝对路径覆盖、符号链接逃逸、解压炸弹；可暂时延后复杂归档能力。
- Sandbox 下需要兼顾用户选择的安全作用域 URL、书签持久化、Finder 来源路径访问能力；**拖拽监控不要求辅助功能权限**不等于任何源目录读写都不用系统授权。

### 5.5 完成验收

拖动单张 HEIC → JPG 成功；十张混合文件正确判断格式与跳过策略；重名不会覆盖；Esc 取消；源文件始终存在；其他全屏 App 和第二显示器不乱弹；转换失败可复现和理解；空闲 CPU 不明显消耗。

## 6. 功能二：屏幕 AI 助手

### 6.1 出现方式

按 `⌘ ⇧ Space` → **屏幕底部中央**先出现黑色小胶囊，宽约 136pt、高约 42pt（仅设计基准）→ 自动获得输入焦点时扩展为宽约 380–460pt、低矮的对话输入框 → 需要查看更多回答时按内容扩展到合理高度，最大不能挡住整个屏幕。收起时反向形变，而不是突然消失的网页聊天卡片。

AI 不应该默认持续偷窥屏幕；胶囊唤起后用户可以直接问普通问题，也可以主动选“当前截图”“框选区域”“当前选中文本”。

### 6.2 V1 功能范围

- 基础对话，流式显示回复，复制、重试、继续追问。
- 当前截图：用户点“截取当前屏幕/窗口”后显示将发送的缩略预览，并明确告知发送给哪个模型服务商，确认后发送。
- 选区：调用共享的 `CaptureService`，框选后可 OCR 或将图片发给模型；可只发送 OCR 文本，减少 Token 和敏感图像传输。
- 可选当前文本：优先采用用户主动复制/粘贴或明确授权的选中文本入口；跨应用自动读取的实现与权限作为工程验证项。
- 持续感知：显式开启后出现常驻小提示“持续感知中”和“一键停止”；可调整更新频率。V1 推荐仅在用户打开助手并发起连续任务的会话期间更新，**不做 24 小时后台摄屏**。
- BYOK：至少一种模型服务商可配置，新增服务商通过统一 `AIProvider` 协议扩展；API Key 存 Keychain，密钥从不进入日志、错误上报或明文 JSON。
- 模型请求失败要保留用户问题、允许重试；不伪造“已理解屏幕”成功状态。

### 6.3 代码架构

- `GlobalHotkeyService` 注册全局快捷键，先做冲突检测；不得用需要额外权限的全键盘监听来冒充简单热键注册。
- 使用 `NSPanel` 的 `.nonactivatingPanel`，根据需要控制成为 key window、保留原应用前台身份；支持 `.canJoinAllSpaces`、`.fullScreenAuxiliary`，但要在 macOS 不同版本验证实际焦点行为。
- SwiftUI 只负责胶囊与内容视图；`AssistantPanelController` 负责窗口定位、动画、显示/收起、焦点恢复、键盘关闭。
- `AIService` 统一处理 Provider、流式请求、取消与超时；请求和日志去敏感；只在真正需要发送截图时附带图片。
- `KeychainService` 调用 Security Framework 的 `SecItemAdd`, `SecItemCopyMatching`, `SecItemDelete`；本地配置只保存 provider id、模型名和非敏感偏好。
- 截图经 `CaptureService` 生成；上传前生成明确且可撤销的用户提交动作。

### 6.4 UI 细节

胶囊：黑色背景，左边 ScreenBuddy 抽象小标记或小型蓝色呼吸点，右边最少文本。不要一圈大霓虹蓝光。输入面板顶部不做传统“AI 聊天室”标题栏；右侧小型功能图标切换上下文；底部可只有“当前截图 / 框选 / 发送”三个最常用入口，复杂设置不应塞进面板。

### 6.5 完成验收

快捷键连续开关十次不抢焦点、不残留幽灵窗口；在 Safari/VS Code/Finder 全屏下可唤起；BYOK 真实请求流式完成；用户未授权截图时任何图片不会发送；取消网络请求后窗口不会持续转圈；持续感知停止后立即停止后台任务。

## 7. 功能三：文件暂存架

### 7.1 用户体验

用户从 Finder 拖一个或多个文件到显示器的左/右边缘，出现窄条预提示，继续靠近时从边缘弹出文件暂存架。松手后只是保存对原文件的引用，不移动、不复制原文件。之后可以将文件从暂存架拖进邮件、浏览器上传框或其他应用。暂存架有 Quick Look、批量拖出、移除条目和清空入口。

### 7.2 悬浮形态

未触发时不占用空间；如果有暂存文件，可保留极窄边缘提示条和数量（用户可关）。靠近边缘后，黑色半透明竖向窄条滑出，展示缩略图叠层。手势交互要允许拖进来，也允许拖出去；不能因收起太快而丢失文件。贴边位置要记忆，多显示器时按所属屏幕复原。

### 7.3 底层做法（已实际读 OpenShelf）

- `ShelfPanel` 使用无边框 `.nonactivatingPanel`、`isFloatingPanel`、`.canJoinAllSpaces`、`.fullScreenAuxiliary`，还能接 Quick Look 控制。
- `ShelfWindowController` 保存 `shownFrame`、贴边状态、动态高度；悬浮文件增减后刷新尺寸；鼠标离开时有延迟隐藏；用户主动展开后持有“直到用户真正访问过”标记，防止立刻缩回。
- 参考源码使用约 250ms 的边缘位置检查周期，但实际频率应测量后调整；闲置无暂存文件时关闭相关计时器。
- 持久化使用安全书签或合规 URL 权限机制，重新启动时检测文件缺失和权限失效，显示“原文件已移动/不可访问”，支持移除，不私自复制文件填补。
- 拖放由 `NSDraggingDestination`/SwiftUI drop delegate 等按场景处理；Quick Look 走 `QLPreviewPanel`/QuickLook 框架。

### 7.4 完成验收

拖入 20 个不同文件不移动源文件；拖出文件到其他 App 符合其原生拖放语义；文件被手动删除后不崩溃；改变显示器布局后不会跑到屏幕之外；暂存架隐藏时不吞掉 Finder 边缘普通拖拽。

## 8. 功能四：智能剪贴板

### 8.1 出现方式与内容

按 `⌘ ⇧ V` 在当前屏幕显示一个小而快的搜索面板：上方搜索框、下面列表（文字片段、链接、图片、文件，按实际类型区别图标），支持键盘上下选择、回车复制/粘贴、收藏常用片段、清空历史。Esc 关闭；不要打开完整管理网站。

### 8.2 实现（已读取 Maccy/Clipboard.swift）

- 定时对比 `NSPasteboard.general.changeCount`；Maccy 默认约 **0.5 秒** 轮询，ScreenBuddy 可采用类似配置，测试真实 CPU 与响应速度。
- 保存 `.string`, `.rtf`, `.html`, `.png`, `.tiff`, `.fileURL` 等支持类型；同次复制多个 pasteboard items 组合为一条记录，避免重复。
- 跳过 `.concealed`, `.transient`, `.autoGenerated` 等标记；支持排除 Bundle ID 和正则匹配内容；对密码管理器及其他敏感 App 采取保守默认规则。
- 历史记录离线保存、可限制条数与保留天数；固定收藏不受普通历史数量限制。敏感内容不可默认云同步、不可写明文日志。
- 选中历史后有两个动作：**复制到系统剪贴板**（通常不需辅助功能权限）与**自动粘贴到原应用**（可能需要模拟 `⌘V`，需要相应辅助功能信任）。缺权限时明确降级为“复制成功，请手动粘贴”，不骗用户。
- 去格式粘贴保留 `.string`，但对文件 URL 有专门逻辑，避免拷贝文件丢失；“纯文本粘贴”与“保留格式”要区分。
- 对应用自己写入系统剪贴板的行为打标，防止无限重复记录自身产生的内容。

### 8.3 UI 和隐私细节

可选搜索栏“搜索复制记录”，列表每条最多两行，大图仅显示缩略图，敏感内容不自动显示预览。右侧轻量菜单含“固定”“删除”“复制纯文本”。不做 AI 自动分析所有剪贴板内容；要发给 AI 必须用户主动选择“询问 ScreenBuddy”。

### 8.4 验收

20 次跨 App 复制不漏记录；文件复制可再次粘贴；富文本可按选择保留/去格式；密码管理器样本不入库；应用进程退出时轮询清理；关闭开关后不会再收集新的复制事件。

## 9. 功能五：超级截图（包含翻译，绝对不能漏）

### 9.1 核心流程

按 `⌘ ⇧ X` → 光标进入截图模式 → 用户框选一块区域或选择窗口 → 选区确认后出现一条**就贴着选区的黑色小工具条** → 工具条只有 `复制`、`OCR`、`翻译`、`标注`、`贴图`、`问 AI` 六个操作（空间不足可横向收起部分功能）→ 执行完成后工具条自行收起或进入对应编辑浮窗。整个过程不打开主设置窗口。

### 9.2 功能逐项定义

**复制**：将所选截图写入 NSPasteboard 图像格式，可立即粘贴至微信/邮件/文档；可选“复制为文件”。

**OCR**：使用 Apple Vision 在设备上识别中文、英文和混排文字；结果呈小浮窗，可选择、复制全部文字、复制单行；二维码或链接识别是锦上添花，不影响首发。

**翻译——V1 必做**：
1. 用户框选有文字的画面，点击“翻译”。
2. 使用 Vision OCR，识别文字与位置，优先合并为合理阅读顺序的段落。
3. 选择源语言“自动检测”或手动指定，目标语言默认简体中文（可更改）。
4. 优先使用 Apple `Translation` 框架，在当前设备支持的语言对上调用 `TranslationSession`；首次缺少语言包时由系统引导下载/授权，不能默默把文字上传第三方。
5. Apple 引擎不支持语言或实际不可用时，显示明晰提示，用户可主动选用已配置的自带模型 API Key 翻译；需要互联网和发送文字时应明示。
6. 翻译结果放在选区边缘的小浮窗，支持“原文 / 译文”切换、复制译文、调整目标语言。
7. **原位覆盖翻译**是进阶模式：根据 OCR 的每个文本块位置覆盖译文，保留原截图布局。背景修复、换行、字体缩放与右到左文字情况复杂；V1 可先用半透明覆盖层实现清晰可读的替换，不对任意复杂背景承诺无痕修复。仅当质量达到验收标准再作为 V1 可用选项开放。

**标注**：截图缩略编辑器支持箭头、矩形、画笔、文字、马赛克/模糊、撤销重做；拖拽、缩放和颜色选择保持克制，默认仅黑/白/品牌蓝。

**贴图**：把截好的图片保持为可移动的独立置顶窗口，支持缩放、透明度、关闭、临时穿透点击（可选）；不会默认保存到云端。

**问 AI**：用户明确点击后将截屏加入 AI 面板预览，确认发送后按 BYOK 调模型；如果只需要文字解释优先提供“仅发送 OCR 文字”选项。

### 9.3 实现路线（已阅读 macshot 源码）

- 截图：`ScreenCaptureKit` 的截图能力和授权体系，选区 UI 使用独立透明覆盖窗口；根据 API 的系统版本做适配。截图过程中正确处理不同显示器的坐标和 Retina 像素比。
- 优化：macshot `ScreenCaptureManager.swift` 有缓存 `SCShareableContent` 的实现，**约 2 秒缓存有效期**，用于降低反复枚举延迟。先测量再决定缓存寿命；热键触发时可预热。
- macshot 针对触发截图瞬间前台菜单消失的问题有单独捕捉策略；ScreenBuddy 需确保捕获用户触发时看到的内容，而不是 AI/截图浮窗盖上后的内容。
- Vision OCR：`VNRecognizeTextRequest` 或 macOS 新版 Vision 的 `RecognizeTextRequest`；优先首选中文语言，混排测试；需要对超时/取消/低置信度做降级。
- Apple Translation：macOS 15+ 为 V1 目标；采用 `TranslationSession`（合适时通过 `.translationTask` 或受支持的直接初始化），动态检测支持语言。要区别“识别图中文字”和“翻译文字”，两步都可能失败。
- 标注：独立可测试的图形画布；撤销栈；渲染与原始截图分开；导出保持正确像素尺寸、色彩空间。
- 贴图：独立 `NSPanel`，窗层置顶、透明度设置、多个贴图实例管理；关闭某张贴图不影响屏幕截图服务。

### 9.4 完成验收

截图快捷键在 Finder、Chrome、全屏 VS Code 下可用；多显示器选区坐标准确；中文/英文 OCR 识别效果达到人工可用程度；至少一个 Apple Translation 支持的语言对成功翻译；语言包缺失能明确引导；复制译文正确；贴图可拖动/关闭；标注保存不损坏原始截图；问 AI 前显示内容范围并确认。

- 每个第三方库先固定 Git commit SHA/tag，建立 `THIRD_PARTY_NOTICES.md`、LICENSE 追踪表、依赖版本记录。许可证是否允许将源代码直接拷贝进闭源商用版本，必须单项核对；不能把 MIT 的判断套用给所有项目。
- **优先读源码吸收架构与交互，再用自己的模块实现**，避免简单复制五个 App 并联造成维护困难。
- 有外部二进制、FFmpeg、图像编码库时核查许可证、签名、分发、体积、沙盒兼容。
- 每个承诺“零上传”“无需辅助功能权限”“完全离线”的功能都要做独立验证；AI 主动请求会联网，不能对整个 ScreenBuddy 宣称完全离线。

### 11.3 共享接口原则

- `FeatureRegistry`: 五项功能的 enabled/disabled、启动/停用、权限状态、快捷键；设置开关调用 `start()/stop()`，不是 UI mock。
- `FloatingWindowCoordinator`: 统一控制浮窗相互遮挡、激活/非激活策略、全屏、显示器、Z-order；同一时刻截图选区会临时压过其他自家浮窗，并在截图中排除自家工具界面。
- `GlobalHotkeyService`: 处理注册/注销/冲突，自带重绑定流程；如果注册失败展示明确状态，不悄悄使用备选键位。
- `PermissionCoordinator`: 按场景展示系统权限缘由、当前状态、跳转系统设置、授权失败后的功能降级；不能依赖不可靠的自行修改系统授权。
- `LocalTaskQueue`: 文件转码、OCR、翻译等耗时任务统一可取消；避免主线程执行 CPU 密集操作。
- `DemoTimeline`: 专管演示动画序列，不触碰文件、系统事件、API 密钥；演示按钮即使真实功能关闭也可以允许播放（是否允许按用户偏好，默认建议可以，以便了解功能）。

### 11.4 隐私和权限表（实际需在目标 macOS 测试）

| 功能 | 常见需要的能力 | 权限处理原则 |
|---|---|---|
| 圆盘 | 全局鼠标事件副本、拖拽 pasteboard、源文件读取与输出目录写入 | 不自动认定需要辅助功能权限；针对目录读写遵守系统文件保护和沙盒规则 |
| AI | 全局热键、可输入浮窗、屏幕截图、网络请求 | 屏幕获取经明确授权；Keychain 保存密钥；发送第三方前告知 |
| 暂存架 | 文件拖放、Quick Look、可能的安全书签 | 仅保留文件引用；不绕过目录访问限制 |
| 剪贴板 | NSPasteboard、部分情况下模拟粘贴键盘事件 | 历史本地保存；自动粘贴按权限状态降级 |
| 截图翻译 | ScreenCaptureKit、Vision、Translation；可选云端模型网络 | 用户自主框选；翻译优先系统框架；需要语言包时说明；云服务须主动选择 |

**特别提醒**：Apple global event monitor 对键盘事件监视有辅助功能要求；不要把“读取修饰键状态”混同“可随意监听全局按键”。ScreenCaptureKit 亦要求在捕获前遵循系统许可。不同 API、打包方式（沙盒/非沙盒）、macOS 版本需要逐一核查。

## 12. 演示动画的具体分镜：交付时必须完成五段

**共同规则**：每个演示均在同一个弹窗框架里，点击“演示”自动播放；舞台右上只有 `↻ 重新播放` 按钮，弹窗标题栏右上 `×`；没有底部描述；用户可中途重播；结束停留最终画面；Esc 关闭。建议每段约 4–7 秒，由真实可复现的状态序列驱动。此处时间只是分镜建议，不是等待或任务耗时承诺。

### 12.1 圆盘分镜

- 0.0s：显示 Finder 与一张 `照片.heic`，鼠标移向文件。
- 0.5s：鼠标按住文件并拖动，文件图标随之移动。
- 1.2s：按 Shift 的短暂键盘视觉提示，鼠标旁圆盘从缩小/旋转态以弹簧伸出。
- 1.9s：鼠标沿圆盘移动，当前扇区平滑高亮蓝色，中央文字变为 `PNG`。
- 2.9s：松开鼠标，圆盘快速收回；Finder 中出现 `照片.png`，原 `照片.heic` 仍保留。
- 4.1s：停在最终 Finder 画面；重播按钮始终在舞台右上。

### 12.2 AI 分镜

- 0.0s：Finder 或浏览器场景，展示快捷键 `⌘ ⇧ Space`（提示在场景内短暂出现）。
- 0.7s：底部中央一个黑色小胶囊快速弹出，蓝色指示点微弱呼吸。
- 1.5s：胶囊平滑变宽为输入面板；用户输入“解释这张图”。
- 2.5s：点击“选区”，桌面上一个蓝色截图选框出现；用户选中后看到预览。

- 5.0s：停在展开状态，便于用户看清楚设计。

### 12.3 暂存架分镜

- 0.0s：从 Finder 拖一张图向屏幕右边缘。

- 3.4s：鼠标离开，暂存架缓缓收起，边缘留一个轻量提示。
- 4.5s：停在收起状态。

### 12.4 剪贴板分镜

- 0.0s：在 Safari 复制一行文字。
- 0.8s：短暂演示 `⌘ ⇧ V`。
- 1.4s：搜索面板弹出，显示最近三条（文字、链接、图片）。
- 2.3s：输入关键词，列表实时过滤；选择一条。
- 3.4s：面板收回，内容粘贴到原应用的示意输入框。

### 12.5 超级截图 + 翻译分镜

- 0.8s：屏幕其他区域变暗，用户拖动蓝色选区。

## 15. 难点与必须诚实标注的风险

1. **全局 Finder 拖拽与弹出圆盘**：事件监听、拖拽 pasteboard、第三方 App 拖拽行为以及落下文件的命中反馈，都需真机验证；部分 App 可能使用自定义拖放机制。
2. **权限与沙盒**：macOS 全局监测、受保护目录、截图、自动粘贴的权限不可混为一谈；是否在 Mac App Store 发布将影响沙盒与分发策略，必须提前定。
3. **Apple Translation 支持差异**：设备系统版本、下载模型、语言对均会变化；不能一开始保证全部语言离线。
4. **原位覆盖翻译**：OCR 几何区域、背景修复、排版自动换行可能使图片复杂；先交付可用译文浮窗，再做高质量覆盖。
5. **AI 连续感知成本与隐私**：用户自付 Token，但仍需防止不知情的持续请求；默认关闭、频率限制、清晰状态提示、及时停止。
6. **系统快捷键冲突**：必须可更改，不可暗中覆盖系统或其他 App。
7. **第三方许可证与商业分发**：核对使用代码的许可要求、版权 notices 和二进制分发；UI 借鉴不代表可复制资源和商标。
8. **尚未验证所有 GitHub 仓库内部实现**：本交接仅对已阅读文件和 README 分别作出了判断，后续编码前仍应核查版本和完整依赖。

**最终设计原则**：用户打开 ScreenBuddy 时只看到一个极简控制中心；用户真正使用 ScreenBuddy 时，工具出现在当下最合理的位置，动作尽可能少、反馈足够清晰，用完后自然消失。截图、翻译、AI、转换、暂存和剪贴板都用同一套窗口、动效和安全理念。**绝不重新做成一个让用户来回跳转的网页工作台。**
