# HTML → Word 背景验收记录

对照：LibreOffice 官方说明其 HTML 导入以 CSS2 为限；GenOffice 的 HTML→DOCX 架构使用浏览器布局与 Word 元素重建。实际检视 dom-docx（MIT，26ca34eaede79e098451d6dd2a5c8bea647757ec）与 XonLoke/html-to-docx（README 标注 MIT，0f525ba8b1baeba31849654ea0000aa265f20bad）源码，前者的计算样式仅采集背景色，后者读取背景色和图片替代文本；未发现 CSS 元素背景图片转换，因此未引入。

- 仅支持显式 `height:100vh` 的短单块正文页面背景 `cover`、`center` 或像素起点；输出仍保留原生文字。一般多页 body 的 cover 尺寸基于整个 body，不可等同每页 cover，因此走既有带提示的回退。
- 元素背景仅覆盖唯一短单段文字（最多八个中英文字符）、无嵌套、显式 200–500px 宽 / 25–300px 高、本地图片、`background-size:100% 100%` 和 `no-repeat`，并以 Word 文字下方、相对段落的图片锚定。其他场景继续提示背景可能丢失；不是任意 CSS 保真。
- 使用随包 LibreOffice 实际转换，中英文段落与页面背景在 DOCX XML 中为原生文字与图片，中文“你好世界”及图片在 Microsoft Word 中实际显示；Word 未激活，无法测试编辑。样本保留源文件，复杂 cover 和超过八字段落不套用未经验证的背景。后续改动仍需重新验收。

参考：https://github.com/genspark-ai/genoffice/blob/main/packages/html2docx/ARCHITECTURE.md ，https://help.libreoffice.org/latest/en-US/text/shared/optionen/01030500.html

补充：对唯一无嵌套的单行单列单元格，使用相同受限本地背景规则，修复 LibreOffice 把单元格压缩到文本宽度的问题：仅在 Word 结构确定为单表单行单元格时按 CSS 恢复宽高，再将图片锚定在单元格文字下。中文“你好世界”样本在真实 Word 显示为单行、背景未错位；XML 检查原生文本、图片、宽高；多单元格样本确认不套用该单格规则并保留保真提示。该方案不涵盖一般多行多列、合并、重排或嵌套表格。Word 未激活，编辑验证仍缺。

进一步扩展：单行两列、显式 `border-collapse:collapse`、各格具有不重复的短中英文文字、相同固定高度和各自固定宽度、本地图片并以 100% 拉伸的受限表格，可输出为保留原生单元格与文本的 Word，并在文字下绘制两格组成的背景层。合成中文两格文件在真实 Word 中显示各格背景与文字对齐；此机 Word 未激活，不能验证编辑后重排。缺少 collapse、重复文字、三列或更复杂结构会继续普通转换并显示背景保真提示。该背景为整行图片，编辑调整列宽后不会自动重新排列，不应作为完整 CSS 转换宣传。

多行扩展：对显式合并边框、固定等宽等高、每格有独立本地图像且短文本不重复的 2 行 × 2 列表格，使用合成的表格后置背景，恢复两列宽及两行高度，保留 Word 原生单元格文字。自建样本在 Word 实际观察首行红蓝、次行绿色及中文均对齐；结构和源文件保护测试通过。总尺寸限宽 500px、高 400px，以降低分页风险。更复杂行列、合并、尺寸不一致、三行或三列、重复文字均回退并提示；背景不是独立的单元格纹理，编辑表格尺寸不会跟随，Word 未激活无法验证编辑行为。

2026-11-12：受限固定尺寸短文本段落和前述受限表格的每个单元格，新增本地图片 `background-size:cover; background-position:center; background-repeat:no-repeat`；按元素盒子计算中心裁剪后嵌入，源 HTML 不变，仍保留 Word 原生文字。自建三色图片与中文样本经随包 LibreOffice 转 DOCX，断言原生文字、背景嵌入及裁剪像素；用本机 Microsoft Word 实际打开，确认中文在红绿蓝背景上方显示、居中裁剪正确（Word 未激活，未验编辑）。同一个 DOCX 用 LibreOffice 再导出 PDF 时背景会遮住文字：该跨阅读器问题仍未解决；非居中、嵌套、复杂 CSS、跨页等仍回退并提示，不能宣称完整 CSS 保真。

后续复核更正：上述“背景遮住文字”是误判。同一文件去掉背景后中文仍不可见，英文在背景前可见；原因是随包办公引擎的 fontconfig 没有找到系统中文字形。现已在启动办公引擎时指定 macOS 系统字体目录及专用字体缓存（不随包分发系统字体，不依赖开发机用户字体目录）。通过 MORIQ 自身转换链将该 DOCX 转 PDF，合成样本的中文文本层和背景上黑色文字像素均通过；先前页面背景与超链接回归也通过。本机真实 Word 的中文和背景显示正确；尚未在全新 macOS 或实体 Intel 检查字体环境。
