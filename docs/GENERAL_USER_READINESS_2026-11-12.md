# MORIQ 普通用户首次使用审查

2026-11-12 基于当前源码和 `/tmp/moriq-font-signed-build/Build/Products/Debug/MORIQ.app` 的静态检查与隔离测试；没有读取用户钥匙串或发送真实请求。结论仅代表所列证据范围，不代表正式版可发布。

## 首次使用中的实际依赖

| 项目 | 当前行为与证据 | 普通用户缺口及建议 |
| --- | --- | --- |
| AI 服务 | AI 服务客户端默认从本机钥匙串读取用户配置的密钥；没有密钥即 `noKey`。`AI 连接`页要求填写密钥并说明请求会发送给 AI 服务和可能产生费用。无用户密钥时不可使用该 AI 服务；没有发现产品账号、平台代理或随应用可用的默认服务。隔离 AI 测试使用模拟服务验证缺密钥、401、流中断等；没有读取本机凭据。 | **发行阻断：**不能假设普通用户会申请和管理密钥。若产品决定提供开箱即用 AI，需要设计服务端代理、用户认证、配额/计费、滥用控制、隐私说明和故障恢复，并自行部署及验收；不要把共享密钥放入客户端。也可另行评估符合设备性能要求的本地模型。具体路线、成本和服务账户尚未确定，不能承诺已实现。用户自带密钥可作为进阶方式。 |
| AI 无网/失败 | 断网、超时、401、402、429、流中断及缺失密钥有中文错误映射；无网无法完成云端 AI 问答。模拟服务通过；真实账号额度、后台服务、重连和新用户全流程未验收。 | 产品应在连接入口明确显示可用状态，给出可直接到达的配置/重试动作；无网时保留输入和可用的本地工具。禁止将网络不可用描述为内容识别成功。 |
| 系统语音识别 | 字幕优先使用本机识别。当前 `CaptionAnalyzerAvailability.enabled = false`，新系统分析器路径及其 `AssetInventory` 自动下载代码不会运行；实际走 `SFSpeechRecognizer`，要求 `supportsOnDeviceRecognition` 和 `isAvailable`。不可用时提示尝试在系统听写设置添加语言或切换语言；该提示不是保证能成功安装。 | **发行阻断：**在干净用户、支持的 macOS 版本和四个语言上确认本机语音资源的检测、安装/系统引导、进度、失败与重试；先解决分析器当前已记录的崩溃再考虑启用，不可只因存在下载代码就宣称自动下载已实现。 |
| 本机翻译语言包 | 字幕用 `LanguageAvailability` 检查语言对；`.installed` 才启动翻译，`.supported` 提示用户去系统设置下载，`.unsupported` 提示不支持。不同机器的语言资源状态不同；支持某语言对不等于已经安装。 | 在首次准备流程中清楚说明每种语言包的状态、占用和下载入口；对无网、下载中断、不支持和稍后恢复分别提供反馈。须在干净系统按实际语言组合验收，不把当前机器安装状态当作所有用户已安装。参考 [Apple LanguageAvailability](https://developer.apple.com/documentation/translation/languageavailability)。 |
| 授权和静音首次启动 | 用户此前要求所有授权前置。目前 `AppFlow.mayEnter` 同时依赖屏幕录制、辅助功能、桌面/文稿/下载文件夹、直接屏幕读取、语音识别和本次系统音频验证。系统音频首次探测若处于静音且没有既往成功记录，会提示播放声音后重试，整个入口不能进入。直接屏幕读取与音频验证使用系统采集 API；系统仍可能再次弹出自己的提醒。 | **发行阻断：**保持用户已确认的全授权门禁，不擅自把静音当作授权。应验证是否存在无需依赖外部正在播放内容、仍能真实验证系统音频权限的前置检测方案；如无，应在页面上清楚引导播放一段可控测试声音并允许重试。需真实干净账户验证拒绝/重开/静音/系统提示及撤销恢复；目前没有证明所有新用户均可顺利完成。 |
| 包内依赖 | 文档、媒体转换优先选择随包 Office、PDF 运行时、Pandoc 和 FFmpeg，对不同 CPU 选择对应二进制。代码也保留本机安装路径及开发环境路径回退；缺少随包组件时不应依赖开发机恰好安装的工具来证明普通用户可用。 | 对最终发行物按两种架构、没有 Homebrew/开发环境的干净用户验收；对缺失、无执行权限、损坏和依赖启动失败分别明确报错并保护原文件。清理或隔离仅适合开发环境的回退路径。 |
| 平台与发行 | Info.plist 最低 macOS 15.0；当前检查的 Debug 主程序只有 arm64，虽然部分随包引擎包含两个架构。Developer ID、公证、真实 Intel、全新系统安装尚未完成。 | 只有发行包主程序和所有必须组件均验证对应架构、并在 Apple Silicon 与实体 Intel 实机通过后，才宣称双架构支持；签名、公证及升级回退单独验收。 |

## 本轮完成的独立改进

- 新增 `Tools/Release/check_bundle_dependencies.py`：离线只读检查已知应用二进制的架构与可执行性、两架构引擎、JAR CRC、必要资源和 Info.plist；不读取钥匙串、不启动用户应用、不发网络请求。其隔离测试 `python3 Tests/ReleaseDependencies/test_check.py` 覆盖正常、缺文件、损坏、错误架构和无效 plist。
- 对当前 Debug 候选执行体检：已列资源及 JAR 检查通过，主程序仅 `arm64`，因此体检报告 **1 项失败**。这与只在当前 Apple Silicon 上构建 Debug 一致，不代表最终 Release 架构或真实 Intel 已测试。
- AI 测试使用内存模拟服务与虚构密钥注入，确认缺钥匙、HTTP 失败和流不完整等基本分支；没有读取用户真实密钥或请求外部服务。通过范围不包括新用户产品接入。

## 建议的验收顺序

1. 产品确定普通用户 AI 服务路线及明确成本/数据处理方式，准备真实但可撤销的测试账户；以干净账户验证首次使用、无网、余额/配额和恢复。
2. 不降低既定授权门禁，解决系统音频在初次静音下的真实可验证流程；从无权限用户账户验收完整引导与重启。
3. 修复并验收字幕本地语音资源准备；用干净机器分别测试语音语言资源和翻译语言包，覆盖无网、下载失败和重试。
4. 用 `check_bundle_dependencies.py` 检查实际签名候选，在无开发依赖的两种架构机器验证转换；分别完成签名、公证、许可证、安装和回滚检查。
