# 多人字幕：时间对齐基础与接入约束

## 当前状态

目前 MORIQ **没有实现说话人分离或真实姓名识别**。实时字幕使用系统声音；同声传译模式的代码使用系统声音和麦克风两条独立采集与识别路径，同一悬浮窗口分别呈现两路。系统声音仍可能包含多个人，不能根据来源、文字或声道推定某个具体人。`CaptionHistoryEntry` 仅保存原文、译文和语言，不含说话人身份。

双路模式已通过构建及隔离合成测试：分别将两段内容不同的合成语音送入两条 sink 和两个本机识别进程，检查两路识别、交叉来源拒绝和停止后不再接收。测试没有启动真实双路采集，也没有使用麦克风；真实设备、授权、音源切换、两路翻译及界面仍需端到端验收。在线服务尚未部署。

`Vendor/SpeechEngine/main.cpp` 当前以 16 kHz 单声道 PCM 输入、2 秒步长推理、每 4 次提交并保留约 200 ms 音频重叠；输出为 `P\t文本` 或 `F\t文本`。当前没有向应用提供词级时间戳；一个提交窗口也可能包含多个人。因此不能给整个窗口直接贴说话人标签。

## 本次基础接口

`MORIQ/CaptionSpeakerAlignment.swift` 定义词区间、匿名说话人区间和对齐结果。区间使用**同一条 16 kHz 音频时间线上的绝对采样下标**，采用左闭右开约定。调用方必须提供来自实际引擎的词时间戳、说话人区间和经标注数据校准的覆盖率及竞争阈值；接口没有生产默认阈值。覆盖不足、存在竞争或输入无效时返回未知，而不是猜测。相同说话人的重叠区间先合并，避免重复累计覆盖率。

此接口为独立数据处理基础，**未接入字幕管线，未运行说话人模型**。`sh Tests/CaptionSpeakerAlignment/run.sh` 使用合成的时间区间检查边界、多人竞争、重叠、重复数据和无效输入；通过这些测试不代表在真人音频上的准确率。

`CaptionSpeakerNames.swift` 是另一个未接入运行时的会话内数据模型：匿名 ID 首次出现时分配展示编号，只有用户明确编辑时才保存姓名；用户可对单段更正说话人或标为未知，亦可撤销更正。新会话清除编号、姓名和单段更正，旧会话回调不能修改新会话。它不采集或持久化声纹，不进行跨会话身份识别。`sh Tests/CaptionSpeakerNames/run.sh` 覆盖这些规则。未来接入时应由主线程或 actor 串行持有，为每个字幕稳定段分配 UUID，仅为真实且明确的分离结果登记 ID，低置信度仍显示未知。

## 现有识别器时间信息隔离探针

`Tests/CaptionTokenTimestampProbe/run.py` 在临时目录复制现有 helper 源码，启用其固定版本 whisper.cpp 的 `token_timestamps` 并读取 token 的 `t0/t1`，不修改或替换发行程序。使用公开 LibriSpeech dummy 的 `1272-128104-0000` 约 5.855 秒真人朗读、项目随包 base 模型和本机编译的 whisper.cpp 静态库，输出 49 个 token 时间，其中 4 个区间零时长；非零和零时长区间均位于对应的每个滚动窗口内。重复的滚动推理会多次输出同一句的 token。脚本只输出计数，不打印音频转录内容。

复现需要先按 `Tests/LiveCaptionsRealSpeech/README.md` 准备公开音频，并准备与项目固定提交一致的 whisper.cpp 源码和静态库，然后以 `--whisper-source`、`--whisper-build`、`--ffmpeg` 和 `--audio` 显式指定路径运行该脚本。不将音频或第三方二进制提交到仓库。

这些时间来自真实识别推理，但单位对应窗口内的 10 毫秒 tick，而非生产所需的绝对采样时钟；它们是 BPE token 而非自然语言单词，部分子词或标点零时长。探针只检查了范围，**没有含人工时间真值的对齐误差评估**，也没有验证真实词聚合、窗口间接缝或说话人归属，不能作为高准确度或生产可用的结论。

`Tests/CaptionTokenTimestampProbe/rolling_words.py` 进一步在临时 helper 中累计**连续 stdin 样本**，按窗口起点换算 token 绝对样本位置，聚合英文空格起始的子词，并在同起点的连续推测中检查相同词前缀；跨窗口重置不会自动去重。两段公开朗读拼接后共 170720 个样本，实际得到 6 个滚动窗口、69 个词候选、41 个跨更新重复前缀词；程序检查了范围、提交后的非零窗口起点、拆分子词及 UTF-8 字节再组合。

此探针只证明单一连续输入的基础索引换算和英文 BPE 聚合能运行。连续确认文本不代表词边界时间准确；合并 Unicode 字节也不代表完成中文分词。它未解决窗口交叠处的词去重、真实采集中的队列丢帧或设备切换、话人区间匹配、人工词时间真值或准确率验收，因此没有接入生产。

## 双人拼接录音的离线对齐探索

使用公开 LibriSpeech 两位不同朗读者的录音，按 A/B 交替拼接共 67.59 秒并在片段间留 0.4 秒空白；参考只标记各**源片段**的说话人及时间范围，并不是人工标注的词级时间真值。使用同一音频得到现有识别器的滚动窗口词候选，再与此前分别由 Sortformer 和 LSEEND 离线处理得到的说话人区间做交集。`Tests/CaptionTokenTimestampProbe/evaluate_alignment.py` 接收外部 JSON 结果和参考，不能运行分离器；不需要或包含音频、模型或字幕文本。

本次在 134 个 final 窗口词候选上，**示例**阈值为一个说话人覆盖词区间至少 70%、任何竞争说话人低于 20%。这只是可重复实验参数，不是经过校准的产品阈值。匿名模型编号用同一条音频上的最优映射与 A/B 对齐，带来乐观偏差。结果：

| 离线分离器 | 与片段标签一致 | 与片段标签不一致 | 无分离匹配 | 无片段参考 |
| --- | ---: | ---: | ---: | ---: |
| Sortformer | 121 | 0 | 11 | 2 |
| LSEEND | 113 | 0 | 19 | 2 |

复现时准备上述公开拼接音频及片段参考，先用 `rolling_words.py` 的 `--export-json` 输出词候选，并将同一音频送入所选分离器得到 JSON。再运行 `python3 Tests/CaptionTokenTimestampProbe/evaluate_alignment.py --words /path/words.json --turns /path/turns.json --reference /path/reference.json --minimum 0.7 --maximum-other 0.2`。脚本只输出计数，不打印词内容。

这是无重叠、交替片段的单条构造样本；词时间本身来自识别器而无人工校准，窗口交叠仍可能重复词，分离器为离线处理，结果不反映线上流式延迟，也没有检查识别文本是否听对。“不一致为 0”**不等于零误识**，不能据此宣称高准确率或真实姓名识别。需要不同说话人、多人重叠、背景噪声、真实会话及逐词真值进一步验收。

## 后续接入要求

1. 先选择并评估可发行的说话人分离引擎和模型，包括模型许可、设备兼容性、资源消耗及离线安装方式；用公开授权的多人录音和真值评估。说话人分离只区分匿名人员，不能自动知道真实姓名。
2. 在重采样后 PCM 入口维护绝对采样计数，并让分离器和识别器共享相同起点、采样率和会话代际。当前写队列超限时可能丢数据，须显式记录间断，不能将缺失音频的时间压缩后继续对齐。停止、重启、切换音源、设备变化及重采样器状态变化均需定义时钟边界。
3. 为识别器提供经过实测的词级时间戳，正确将滚动窗口的局部时间换算至绝对样本下标，并处理约 200 ms 重叠、重复词和迟到结果。分离结果也需携带同一时钟的起止位置和会话标识；跨代结果不得污染新会话。
4. 时间对齐时应允许尚未确定的标签和后续修正；保留重叠说话与低置信度为未知，按真实评测校准阈值，避免稳定但错误地分配。词与字幕历史的同步和译文绑定需单独验收。
5. 如需显示真实姓名，必须另有明确的用户标注或经同意的身份注册流程；匿名编号不等于真实身份，不能靠声线或语义猜名字。
6. 端到端验收应包含不同说话人数量、口音、背景声、短句和打断、重叠说话、长会话、音源与设备切换；记录说话人分离错误率、身份混淆、首次出现延迟、修正次数、资源占用，并与所选竞品和用户期望对照。不得仅凭合成单人测试声称高准确率。
