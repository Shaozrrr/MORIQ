# 02｜ScreenBuddy 产品需求文档（PRD）

## 1. 产品一句话

ScreenBuddy 是一款 macOS 原生屏幕上下文助手。用户在任何应用里按下快捷键，就能在屏幕底部唤出一个极简对话框；ScreenBuddy 根据用户授权的当前屏幕内容回答问题，并允许用户连续追问。

## 2. 用户痛点

用户在浏览网页、读 PDF、使用 Excel、看错误弹窗或操作陌生软件时，通常需要：截图 → 打开 ChatGPT → 上传图片 → 输入问题 → 看答案 → 回到原软件。这个过程打断工作流，且追问时需要反复上传上下文。

ScreenBuddy 要减少这类切换，让 AI 在当前工作场景中随叫随到。

## 3. 产品目标

### 3.1 V1 必须做到

1. 快捷键唤出足够快，不抢走用户原来的工作焦点太久。
2. 能可靠捕获用户当前允许的屏幕内容。
3. 将文字与图片交给用户授权的 ChatGPT/Codex 使用额度。
4. 流式显示答案，允许连续追问。
5. 关闭后彻底停止临时捕获，不留下隐形后台监控。
6. 设置统一放在顶栏，主浮窗保持极简。

### 3.2 成功指标（内部验证目标，不是对外承诺）

- 快捷键唤出到输入框可输入：P95 ≤ 300ms（本地机器测试目标）。
- 当前窗口截图成功率：在支持的普通应用场景下 ≥ 95%；受系统保护的窗口除外。
- AI 首字延迟：由网络、模型和账户额度决定，记录真实数据，不承诺固定值。
- 连续追问无需重复选择同一窗口。
- 长答案不被裁切，滚动区域可到达最后一行。
- Esc 后浮窗消失；若 Live 开启，必须明确区分“只隐藏浮窗”和“停止感知”。默认 Esc 只关闭浮窗，不暗中停止用户已开启的 Live；但 Live 状态必须在顶栏持续可见且可一键停止。若用户退出应用，必须停止采集。

## 4. 用户画像与场景

### 场景 A：网页理解
用户在 Safari / Chrome 看一篇英文文章，按快捷键问“用中文总结这篇文章”。ScreenBuddy 捕获当前窗口，发给模型，答案在同一个浮窗里出现。

### 场景 B：软件操作
用户在一个不熟悉的软件里，不知道某个按钮做什么，按快捷键问“这个界面怎么完成导出”。模型基于当前可见界面解释。

### 场景 C：表格分析
用户在 Excel / Numbers 查看数据，问“这张表里最大的异常是什么”。模型只能分析截图/AX/OCR 实际提供的信息，不能假装读取隐藏单元格或整个工作簿。

### 场景 D：连续追问
用户先问“这个套餐是什么”，再问“和上一页有什么区别”。上下文引擎将当前快照和最近相关快照一起组织；找不到上一页时必须明确说缺少上下文。

### 场景 E：持续感知
用户主动开启 Live，选择一个窗口。ScreenBuddy 在本地检测画面变化并保留短期关键帧。用户稍后问“刚才页面改了什么”，系统根据本地缓存的关键帧回答。默认不在后台自动调用模型。

## 5. 核心用户流程

### 5.1 首次启动

1. App 启动后只在菜单栏显示图标。
2. 点击图标打开顶栏 Popover。
3. 显示“连接 AI”和“屏幕录制权限”两个步骤。
4. 用户选择“使用 ChatGPT 账户连接”后，打开官方浏览器授权流程。
5. 用户确认允许 ChatGPT plan usage；只登录身份不等于已授权模型调用。
6. ScreenBuddy 保存本机凭证；不把 Token 发到 ScreenBuddy 服务器。
7. 用户第一次按快捷键时，再按需申请屏幕录制权限。
8. 授权完成后回到浮窗输入状态。

### 5.2 主动提问

1. 用户在任意应用中按 `⌥ Space`。
2. ScreenBuddy 在当前显示器底部中央出现小圆角对话框。
3. 记录触发前的前台应用 PID、窗口候选和显示器。
4. 用户输入问题并回车。
5. ScreenBuddy 捕获当前窗口/选定范围；必要时显示轻微的捕获状态光效。
6. 将文字 + `localImage` 图片输入交给本机 Codex App Server。
7. 接收 `item/agentMessage/delta` 并流式显示。
8. 用户可以继续追问；同一线程保持上下文。
9. 用户按 Esc 关闭。

### 5.3 持续感知

1. 用户在顶栏 Popover 中主动打开 Live。
2. 使用 Apple `SCContentSharingPicker.shared` 选择窗口或显示器。
3. 系统授权后启动 `SCStream`。
4. 本地限频采样、画面差异检测、关键帧去重；可选本地 OCR。
5. 顶栏图标/Popover 明确显示 Live 状态、捕获目标和暂停按钮。
6. 用户提问时，从本地缓存选出相关快照发送给模型。
7. 用户停止 Live 时，停止 stream 并清空临时帧缓存。

## 6. 功能需求

| ID | 功能 | V1 优先级 | 说明 |
|---|---|---|---|
| F-01 | 菜单栏常驻 | P0 | 顶栏只有图标，不显示文字 |
| F-02 | 顶栏设置 Popover | P0 | 所有设置入口集中在顶栏 |
| F-03 | 全局快捷键 | P0 | 默认 ⌥ Space，可自定义 |
| F-04 | 底部极简对话框 | P0 | 默认隐藏、圆角、单一对话框 |
| F-05 | 当前窗口截图 | P0 | 触发前记录目标窗口，避免捕获自己 |
| F-06 | ChatGPT SIWC OAuth | P0 技术验证 | 只走官方授权，不读私有凭证 |
| F-07 | Codex App Server | P0 技术验证 | 本机 stdio JSONL，接收流式事件 |
| F-08 | 本地图片输入 | P0 | 使用 `localImage` 传入临时截图路径 |
| F-09 | 连续追问 | P0 | 保持 thread ID 与上下文 |
| F-10 | 区域截图 | P1 | 自绘选择框，截图后本地裁切 |
| F-11 | 本地 OCR | P1 | Apple Vision；中英优先 |
| F-12 | Live 持续感知 | P1 / Pro 设想 | 用户主动选目标；本地缓存；不默认后台请求模型 |
| F-13 | 变化检测 | P1 | 感知模式下本地差异检测和关键帧抽样 |
| F-14 | 排除应用 | P1 | 用户设置不捕获的 Bundle ID / 应用 |
| F-15 | 本地历史 | P1 | 默认只保存文本和上下文元数据；截图不长期保存 |
| F-16 | 多窗口/前后页面对比 | P2 | 依赖上下文引擎成熟度 |
| F-17 | MCP 扩展 | 后续 | V1 不做 |
| F-18 | 自动操控电脑 | 后续 | V1 不做 |

## 7. 非功能要求

- 原生 Swift / SwiftUI + AppKit，不做 Electron。
- 默认本地优先；ScreenBuddy 不建立模型 Token 代理。
- 不能把用户截图、文本、Key、OAuth Token 写进普通日志。
- 所有系统权限按需申请，不在首次启动时一次性弹完。
- 捕获服务、AI 服务、状态管理和 UI 分层；不得把所有逻辑堆在一个 View。
- 所有异步任务可取消；用户停止捕获后必须释放 SCStream。
- 适配 Retina、多显示器、刘海屏、Dock 自动隐藏和全屏 Space。
- 支持系统减少动态效果；减少动态效果时关闭强动效，保留静态边框状态。

## 8. 不在 V1 范围

详见 `01_DECISIONS.md`。特别是不做 MCP Server、账号云同步、支付后端、模型 Token 充值、自动控制电脑和插件市场。
