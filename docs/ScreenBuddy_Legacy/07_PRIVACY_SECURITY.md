# 07｜隐私、权限与安全

## 1. 基本承诺

- ScreenBuddy 不做云端 Token 中转。
- 屏幕截图和 OCR 默认本地处理。
- 用户提问时，才把当前问题所需的截图/文字发送给用户授权的 AI 服务。
- ScreenBuddy 不会把用户的 ChatGPT OAuth Token 上传到自己的服务器。
- 用户可以随时停止 Live、断开 ChatGPT、清空上下文和退出应用。

注意：当截图发送到 OpenAI / ChatGPT 服务时，内容已离开本机并按对应服务条款处理。不能向用户承诺“屏幕内容永远不离开本机”。

## 2. 权限申请时机

| 权限 | 用途 | 申请时机 |
|---|---|---|
| 屏幕录制 | 捕获当前窗口/显示器 | 第一次主动截图前 |
| Accessibility | 读取可访问 UI 文本 | 用户主动开启增强读取时；非基础必需 |
| 麦克风 | 未来语音功能 | V1 不申请 |
| 通知 | 未来提醒 | V1 不申请 |
| 登录时启动 | 自动启动 | 用户主动开启时 |

不允许首次启动就一次性请求所有权限。

## 3. 敏感内容防护

- 用户可将应用加入排除列表。
- 默认不主动捕获密码管理器、银行/支付类 App 等敏感场景（需建立可维护的 Bundle ID 规则；不能承诺识别所有敏感窗口）。
- 捕获前记录目标应用，若目标已切换或窗口失效，重新确认。
- Live 模式必须清晰显示正在捕获的目标和停止入口。
- 锁屏、睡眠、目标关闭、权限撤销时停止或暂停采集。
- 不捕获键盘输入内容；不做键盘记录。

## 4. 凭证管理

- SIWC access token / refresh token / client registration secrets 存 Keychain。
- 不存 UserDefaults 明文。
- 不写 OSLog、console、analytics、crash report。
- 不将 Token 放到命令行参数；Codex App Server 需要的 access token 通过子进程环境变量 `ACCESS_TOKEN` 传递。
- 子进程环境和诊断输出必须做脱敏；不能打印完整环境变量。
- 断开连接时按官方流程 revoke/logout，清除本地凭证。

## 5. 截图与缓存

- 主动截图：默认只存临时目录，AI 请求完成后删除。
- Live 帧：内存/短期磁盘缓存，数量和时长有上限。
- OCR 文字：默认随上下文一起短期保留；退出或用户清理时删除。
- 本地历史：默认保存对话文字和上下文元数据，不保存原始截图。
- 任何可持久化截图的功能都必须单独开启并说明用途。

## 6. SIWC 特别要求

- 只能通过官方授权流程取得 token。
- 不要用户密码、session cookie 或浏览器 cookie。
- 请求必须来自当前用户本机，并且属于用户主动操作或明确授权的自动化。
- 任何后台 AI 请求必须取得明确同意。
- 不得将一个用户的 ChatGPT plan 用量提供给另一个用户。
- 不得共享、转售或池化 ChatGPT plan usage / OAuth token。
- 不得把 SIWC 变成通用 API 代理。

## 7. 日志与诊断

允许记录：时间、功能名、成功/失败状态、错误类别、耗时、App 版本、系统版本。

禁止记录：截图、OCR 原文、完整问题文本（除非用户主动提交诊断包且清楚同意）、access token、refresh token、API key、用户私人窗口标题。
